# 历史上下文范围

在插件普通配置页的「历史上下文范围」设置，独立于图片模式、群聊流水和工具收纳。默认启用，直接移除最老完整问答轮次，不额外调用模型生成摘要。

```json
{
  "history_budget": {
    "enabled": true,
    "max_chars": 60000,
    "target_chars": 40000,
    "max_group_chars": 12000
  }
}
```

| 字段 | 含义 |
| --- | --- |
| enabled | 开关；关闭后停用历史预算及其标记去重 |
| max_chars | 旧历史上限；包括问答、工具调用参数、结果和旧引用等消息的 JSON 字符数 |
| target_chars | 超限后向这个目标收缩；已落在目标与上限之间时，不为凑字数再丢整轮 |
| max_group_chars | 新旧 Enishi 群聊增量表合计的字符预算，含 META 头；0 表示不单独限制群聊流水 |

默认值集中定义在 settings.py 开头的 HISTORY_DEFAULTS。实际使用填写的数值，不藏额外最低字数或固定保留轮数；上限和目标须为正整数，目标不得大于上限，流水预算须为非负整数。参数不合法时明确报错，不自动改写。

## 保留边界

- 系统提示和当前请求及其完整工具链受保护，不计入旧历史预算。固定工具 schema 也不在历史预算内，因此这不是整次 API 调用的 token 上限。
- 当前用户消息、引用和本轮已经取得的工具结果不按字符截断。任务结束后，它们在后续请求中成为旧历史，才纳入预算。
- 总历史按完整用户轮次处理，调用声明和所有结果保留在同一轮；工具返回的图片消息不另算用户轮次。
- 独立群聊增量块与后面的用户问答关联，不当作独立问答轮次。群聊表格只移除最老的完整消息行，保留原消息 ID、作者、引用、完整图片 URI 及其转义，不截断单元格。
- 新一批流水也受总流水预算约束；在生成本轮保存确认凭据之前确定注入数量，之后保护本轮凭据与增量，避免游标确认与实际注入不一致。
- 只去重本插件生成的独立图片标记，保留每个完整 ID 及来源说明；带普通用户正文的文本不据此删改。

按整轮处理可能使结果低于目标，例如单个旧轮次本身就超过上限；不会用额外魔法字数或固定轮数补回旧内容。当前任务本身很大时，也不会为满足旧历史限制而破坏它。

## 接入与保存

预算在 runner 的 ContextManager.process 边界执行：先完成图片／旧转述清理及工具内容投影，再限制旧历史，随后继续执行 AstrBot 原有上下文管理。发生裁剪后清除已失效的旧输入 token 估计。保留原生 step、_iter_llm_responses 和 execute 的函数身份。

更新后的窗口由 AstrBot 按正常流程保存；直接删除的旧问答不生成摘要。Enishi 原始群消息日志、已归档工具原文文件和 Monitor 已有存档不删除，Monitor 仍完整记录真实 Provider 输入。启用能力收纳以前产生、没有归档引用的旧工具结果，同样可随旧轮次移除。

运行日志及 run_context._enishi_history_budget_stats 记录前后字符数、移除轮数、流水行数、重复图片标记数和受保护内容大小。

## 验证

覆盖整轮工具配对、系统与当前任务保护、流水行预算和保存凭据、图片 ID 去重、可配置小预算，以及原生消息持久化。真实样本的只读重放中，旧历史由 126400 字符收缩至 46170，94 条框架消息变为 25 条，237 条群聊流水保留 133 条；未调用真实模型，未修改生产会话。
