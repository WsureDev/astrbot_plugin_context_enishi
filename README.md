# 渠道图片压缩与查询工具

使用 QQ/NapCat 和 Telegram 原生图片标识管理图片上下文，提供图片转述、取文件、历史发言、头像、成员和单条消息查询工具。适用于 AstrBot 4.28.0 及以上版本。

## 设置方式

在插件设置中打开「渠道图片设置」，添加或展开 **QQ（NapCat）**、**Telegram** 渠道条目，然后配置该渠道。

**图片处理方式**有三个明确选项：

| 选项 | 本轮主模型上下文 | 后续历史 |
| --- | --- | --- |
| 关闭 | 保留 AstrBot 原有行为 | 保留原有行为 |
| 仅本轮消息及引用允许图片内容 | 本轮消息及可达引用中的图片可以用框架原有 Base64 输入 | 图片只保留来源 ID，移除像素 |
| 始终使用图片 ID 引用图片 | 只保留来源 ID；需要查看时调用转述工具 | 保留 ID、转述文字和工具记录 |

引用合并转发的图片范围沿用框架的引用解析深度和获取次数限制。仅本轮允许图片时，其他工具取回的旧图不会自动加入视觉上下文。

**图片转述模型**使用 AstrBot 原生模型选择器。留空时使用 AstrBot 的图片转述模型。**备用图片转述模型**使用原生多模型选择器；主模型失败、超时、不支持图片或返回空内容时，按顺序逐个回退。

**转述结果有效期**默认 `0`，即永不失效。可按渠道设置其他有效期。仅缓存转述文字，不缓存图片文件。**转述最大字符数**默认 4000。

需要分别设置同一渠道的多个机器人或群时，可展开「适用范围」限定实例或群／话题；留空应用全部。更具体的条目优先，同样范围使用最后一个条目。QQ 和 TG 的图片方式、转述模型、备用模型和文字缓存有效期互相独立。

`/渠道图片模式` 显示当前会话匹配的设置。默认 QQ、TG 的图片管理均关闭。

## 图片读取与大小限制

不建立接收时图片索引。图片 ID 包含渠道原生 `file_id`／`image.file`，或原生消息 ID、图片段位置和转发定位。此前未接收过的引用图片，可从引用载荷或 NapCat 按需回取。

**每次读图都重新请求其来源。** 来源已删除、过期或不可访问时，直接返回失败，不使用本地旧图替代。转述文字永久缓存也不会绕过来源读取。转述缓存按图片内容、渠道、模型链、问题和提示词区分，只避免重复调用转述模型。

**达到或超过 16 MB（16 × 1024 × 1024 字节）的图片不调用转述模型。** 已知大小超限时不下载；实际读取后超限时同样拒绝，不尝试备用模型。此限制也覆盖其他工具返回图片的转述。

转述直接使用内存中的图片，不写图片文件。文件型工具需要本地路径时，`fetch_channel_image` 在 AstrBot 系统临时目录生成传递文件。普通文件在本轮结束后删除；交给后台子代理或后台工具时，消费者持有独立临时副本，完成或取消后删除。副本没有缓存索引，不跨任务复用；下次读取仍从来源获取。独立 MCP／其他容器如需消费文件，使用其自己的上传或文件桥接方式。

## 工具

| 工具 | 用途 |
| --- | --- |
| `describe_channel_image(image_id, question)` | 从来源读取图片，由选定模型或备用模型转述，主模型只接收文字 |
| `fetch_channel_image(image_id)` | 从来源获取本轮临时文件路径、尺寸、MIME 和字节数 |
| `get_channel_user_avatar(user_id)` | 取得头像原生图片 ID，随后可以转述或取文件 |
| `get_channel_member_info(user_id)` | 查询当前群成员昵称、名片及角色 |
| `get_channel_message(message_id)` | QQ 从 NapCat 查询；TG 读取当前载荷中的当前／引用消息 |
| `get_channel_user_history(user_id, limit, days, before_id)` | 原有历史发言功能：QQ 分页查询 NapCat；TG 查询已有本地群历史并明确覆盖范围 |

例子：引用一张旧图后，模型调用 `describe_channel_image` 获取文字说明。用于生图时，先调用 `fetch_channel_image`，再把返回的本轮路径传给 `generate_image(reference_images=[path], use_context_images=false)`。

开启图片管理时，通用生图工具的隐式上下文图片缓存入口会提示改用显式参考图，避免旧缓存覆盖新图。

## 框架集成与历史范围

插件通过可卸载的运行时包装实施上下文策略，不修改 AstrBot 源码文件。框架的后台完成事件继承原渠道设置。始终使用图片 ID 时，工具返回图片也通过转述模型变为文字；仅本轮允许图片时，不携带其他历史／工具图片的像素。

TG 相册合并前在现有图片组件上保留原生文件 ID；它不是接收索引，也不要求先见过被引用消息。安装群聊上下文 Flow 时，将来源 ID 保留到它原有的文本记录中。

已有历史如果只剩图片占位符、过期下载链接或没有来源 ID 的 Base64，无法凭空还原原生标识。TG Bot API 没有任意群历史查询接口；历史工具继续只读 AstrBot 的已有本地记录，返回 `source=astrbot_local`、`complete=false`。历史发言逻辑及两项扫描限额保持原样。

## 安装与验证

上传 `dist/astrbot_plugin_channel_media_tools-v0.2.1.zip` 到插件管理，展开渠道条目配置即可。开发过程没有自动安装或修改生产容器。

安装开发依赖后运行：

```bash
pytest
ruff check .
```

设置 `ASTRBOT_SOURCE=/path/to/AstrBot` 可执行该源码中的实际 runner 和消息保存方法；测试不导入应用初始化代码。

验证覆盖原生配置组件、渠道隔离、多级模型回退、默认永久文字缓存、每次读取来源、失效图片不复用、16 MB 大图拒绝、本轮临时文件删除，以及历史发言实现未变。

v0.2.1 修复后台消费者的临时图片期限，并与 LLM 监控的嵌套包装和热重载进行组合测试。设置、历史发言、文字缓存和大图限制保持原样。未安装到生产容器。
