# Context Enishi

Enishi 取日语「えにし／縁」的罗马音，意为缘或联系。`astrbot_plugin_context_enishi` 让 AstrBot 整理提供给模型的上下文，并按需认识聊天中的人和环境。适用于 AstrBot 4.28.0 及以上版本（Python 3.12+），当前支持 QQ/NapCat 和 Telegram。

插件划分为两类独立功能：

| 功能 | 职责 | 默认行为 |
| --- | --- | --- |
| 上下文整理 | 控制图片输入、原生 ID、转述文字缓存和临时文件生命周期 | 图片自动整理关闭，可按渠道开启 |
| 聊天感知增强 | 查询人员、发言活动、聊天环境、消息和头像 | 提供查询工具，不自动向主模型附加环境摘要 |

聊天感知不依赖图片处理模式。关闭自动图片整理仍可查询人员；关闭聊天感知也不影响图片整理。环境查询不会调用转述模型、下载图片或修改消息历史。

现有功能包括：

- 按渠道选择关闭图片管理、仅本轮允许图片，或始终使用图片 ID。
- 使用原生图片 ID 读取引用和历史中的图片，按需转述，提供模型回退和文字缓存。
- 为其他工具提供临时图片文件，并管理普通与后台任务的文件生命周期。
- 查询消息、历史发言、头像和群成员，按需补充模型上下文。
- 群聊人员名单默认按最近发言排序，可改为指定时段内观察到的发言次数从多到少。
- 按需获取群名、当前发言者、引用对象和少量活跃人员；可显式开启有长度预算的当轮摘要。

## 设置方式

在插件设置中打开「渠道上下文设置」，添加或展开 **QQ（NapCat）**、**Telegram** 渠道条目，分别配置「上下文整理」和「聊天感知增强」。两类设置共用该条目的机器人／群／话题范围。

「上下文整理 → 附加当前消息身份与关系」（`context.message_metadata_enabled`）默认关闭。开启后，为当前 user 消息追加一个 `<channel_message_meta>` JSON 块，包含消息与作者 ID、实例与会话范围、引用作者、提及对象、时间来源及原生图片 URI；该块随 user 历史保存，不重复正文。图片模式关闭、聊天感知工具关闭时也可独立使用；自动环境摘要仍只在当轮有效。构建当前 metadata 不查询成员名单或群历史，重复处理同一请求时替换已有块。

消息与历史查询保留旧返回键，新增相同的标准字段。所有身份 ID 使用字符串；缺失 ID 与时间使用 `null`，未恢复的关系标记 `relations_complete=false`。QQ 单条查询最多补查一次引用作者，失败时保留引用 ID 和未知作者；批量历史不逐条补查。Telegram 仍仅支持当前或引用载荷及已有本地历史，本地 `local_record_id` 不作为原生 `message_id`。本轮元数据对齐不改变 Flow 的记录、游标或历史注入方式。完整映射和回滚说明见 [消息字段对齐](docs/message-alignment.md)。

**图片处理方式**有三个明确选项：

| 选项 | 本轮主模型上下文 | 后续历史 |
| --- | --- | --- |
| 关闭 | 保留 AstrBot 原有行为 | 保留原有行为 |
| 仅本轮消息及引用允许图片内容 | 本轮消息及可达引用中的图片可以用框架原有 Base64 输入 | 图片只保留来源 ID，移除像素 |
| 始终使用图片 ID 引用图片 | 只保留来源 ID；需要查看时调用转述工具 | 保留 ID、转述文字和工具记录 |

引用合并转发的图片范围沿用框架的引用解析深度和获取次数限制。仅本轮允许图片时，其他工具取回的旧图不会自动加入视觉上下文。

**图片转述模型**使用 AstrBot 原生模型选择器。留空时使用 AstrBot 的图片转述模型。**备用图片转述模型**使用原生多模型选择器；主模型失败、超时、不支持图片或返回空内容时，按顺序逐个回退。

**转述结果有效期**默认 `0`，即永不失效。可按渠道设置其他有效期。仅缓存转述文字，不缓存图片文件。**转述最大字符数**默认 4000。

需要分别设置同一渠道的多个机器人或群时，可展开「适用范围」限定实例或群／话题；留空应用全部。更具体的条目优先，同样范围使用最后一个条目。QQ 和 TG 的图片方式、转述模型、备用模型和文字缓存有效期互相独立。

`/渠道图片模式` 显示当前会话匹配的设置。默认 QQ、TG 的图片管理均关闭。

## 图片读取与大小限制

不建立接收时图片索引。图片 ID 包含渠道原生 `file_id`／`image.file`，或原生消息 ID、图片段位置和转发定位。此前未接收过的引用图片，可从引用载荷或 NapCat 按需回取。

**每次读图都重新请求其来源。** 来源已删除、过期或不可访问时，直接返回失败，不使用本地旧图替代。转述文字永久缓存也不会绕过来源读取。转述缓存按图片内容、渠道、模型链、问题和提示词区分，只避免重复调用转述模型。

**达到或超过 16 MB（16 × 1024 × 1024 字节）的图片不调用转述模型。** 已知大小超限时不下载；实际读取后超限时同样拒绝，不尝试备用模型。此限制也覆盖其他工具返回图片的转述。

转述直接使用内存中的图片，不写图片文件。文件型工具需要本地路径时，`fetch_channel_image` 在 AstrBot 系统临时目录生成传递文件。普通文件在本轮结束后删除；交给后台子代理或后台工具时，消费者持有独立临时副本，完成或取消后删除。后台消费者新读取的文件也归其自身管理，父任务结束或本插件卸载不会提前删除。副本没有缓存索引，不跨任务复用；下次读取仍从来源获取。独立 MCP／其他容器如需消费文件，使用其自己的上传或文件桥接方式。

## 工具

| 工具 | 用途 |
| --- | --- |
| `describe_channel_image(image_id, question)` | 从来源读取图片，由选定模型或备用模型转述，主模型只接收文字 |
| `fetch_channel_image(image_id)` | 从来源获取本轮临时文件路径、尺寸、MIME 和字节数 |
| `get_group_participants(order, limit, hours, start_time, end_time)` | 最近发言顺序或指定时段观察到的发言次数排行，带数据覆盖说明 |
| `get_chat_environment(limit)` | 群名、当前发言者、引用对象和少量最近活跃人员 |
| `get_channel_user_avatar(user_id)` | 取得头像原生图片 ID，随后可以转述或取文件 |
| `get_channel_member_info(user_id)` | 查询当前群成员昵称、名片及角色 |
| `get_channel_message(message_id)` | QQ 从 NapCat 查询；TG 读取当前载荷中的当前／引用消息 |
| `get_channel_user_history(user_id, limit, days, before_id)` | 原有历史发言功能：QQ 分页查询 NapCat；TG 查询已有本地群历史并明确覆盖范围 |

例子：引用一张旧图后，模型调用 `describe_channel_image` 获取文字说明。用于生图时，先调用 `fetch_channel_image`，再把返回的本轮路径传给 `generate_image(reference_images=[path], use_context_images=false)`。

开启图片管理时，通用生图工具的隐式上下文图片缓存入口会提示改用显式参考图，避免旧缓存覆盖新图。

## 群聊人员与聊天环境

`get_group_participants()` 默认 `order="recent"`，按最近发言由近到远返回最多 30 人。QQ 使用 NapCat 的原生成员快照与最后发言时间；没有可用时间的成员排在后面。TG 只能返回已有本地记录和当前消息中观察到的发言者，不会将其称为完整群名单。

`get_group_participants(order="frequency", hours=24)` 按过去 24 小时中观察到的发言次数排序。可通过 `start_time`、`end_time` 指定 Unix 秒或包含时区的 ISO 8601 时段，例如 `2026-10-10T08:00:00+08:00`。有时段参数的 `recent` 排序也只看该时段里的发言。扫描预算按当前渠道配置，不会找到足够返回人数后提前停止统计。

返回的 `observed_messages` 是扫描到的次数，不是全量发言次数。`membership_complete` 表示原生成员快照是否覆盖已知人员；`complete=false` 不承诺全量历史。结合 `activity.pages`、`stop_reason`、`time_basis`、`coverage` 和 `has_more` 理解结果。TG 使用框架真实的会话及话题键，只读本地历史；记录未开启、已清理或扫描预算不足时会明确返回有限覆盖。当前消息按可用原生／本地记录 ID 去重，无法确定是否已入库时不虚增次数。

`get_chat_environment()` 用于需要了解聊天环境时主动查询。默认不会给每次主模型请求附加成员名单。显式打开「自动附加聊天环境摘要」后，仅附加有字符数和人数上限的当轮文本，不覆盖人格提示词，并利用框架临时内容标记避免保存到后续历史。后台或定时触发会注明是系统触发，不伪造一名群聊用户。

模块边界与后续扩展约定见 [架构说明](docs/architecture.md)。

## 框架集成与历史范围

插件通过可卸载的运行时包装实施上下文策略，不修改 AstrBot 源码文件。框架的后台完成事件继承原渠道设置。始终使用图片 ID 时，工具返回图片也通过转述模型变为文字；仅本轮允许图片时，不携带其他历史／工具图片的像素。

v0.2.2 保留已有监控包装的 `step`、`_iter_llm_responses` 和 `execute` 函数对象，在请求初始化后为每个 runner 的上下文处理器安装图片策略，并在结束状态同步清理历史像素和所属临时文件。不会修改已有监控的健康检查或任务记录。

开启当前渠道图片管理时，后台子代理调用旧 Comfy 的批量工具后，本插件调用 Comfy 已有的回收发送入口，补上主聊天流水线已结束时缺失的接管。保留旧 Comfy 的逐张发送、合并转发、超时和失败报告；正常聊天中的发送仍由原流水线处理。已由 Comfy 接管的批次不会重复接管，重叠批次分别持有其提交状态。接管后的任务在本插件卸载时继续到完成或旧 Comfy 的既有超时，不取消已接受的图片。

此兼容修复只需更新本插件。已用未修改的 LLM 监控 0.4.1 与 Comfy 2.4.2 源码验证。旧监控自身对共享聊天事件的后台子代理调用漏记属于已有覆盖限制，本插件不改写它的任务状态。

TG 相册合并前在现有图片组件上保留原生文件 ID；它不是接收索引，也不要求先见过被引用消息。安装群聊上下文 Flow 时，将来源 ID 保留到它原有的文本记录中。

已有历史如果只剩图片占位符、过期下载链接或没有来源 ID 的 Base64，无法凭空还原原生标识。TG Bot API 没有任意群历史查询接口；历史工具继续只读 AstrBot 的已有本地记录，返回 `source=astrbot_local`、`complete=false`。历史查询补充标准字段，TG 本地查询使用完整会话范围；两项扫描限额保持原样。

## 安装与验证

GitHub 仓库地址：`https://github.com/WsureDev/astrbot_plugin_context_enishi`。发布后可在 AstrBot 插件管理中使用仓库地址安装，或上传 `dist/astrbot_plugin_context_enishi-v0.4.1.zip`。展开渠道条目配置即可。

### 从旧名称迁移

v0.4.0 的插件标识为 `astrbot_plugin_context_enishi`，显示名为「Context Enishi」。旧标识为 `astrbot_plugin_context_manager`（v0.3.0）或 `astrbot_plugin_channel_media_tools`（更早版本）。已有工具名和命令保持兼容。

迁移前备份旧插件配置和文字缓存。独立安装新名称时，将 `data/config/<旧标识>_config.json` 的设置复制到 `data/config/astrbot_plugin_context_enishi_config.json`；如使用配置方案的插件选择列表，也需选择新名称。停用旧插件后再启用新版，避免两份上下文策略同时运行。

旧渠道条目中的平铺图片设置会在启动时迁移到「上下文整理」，保留图片模式、模型、文字缓存和适用范围；「聊天感知增强」默认仅提供工具。迁移只修改本插件自己的配置，原有历史工具实现和根级扫描限额不变。

首次使用新名称时，如果新数据目录尚无转述缓存，依次检查两个旧标识的数据目录并复用已有 `captions.sqlite3`，因此需保留旧缓存目录。已有新目录缓存时优先使用新缓存；不搬移、不覆盖旧文件。迁移过程中仍只保存转述文字，不缓存图片。开发过程没有自动安装或修改生产容器。

安装开发依赖后运行：

```bash
pytest
ruff check .
```

设置 `ASTRBOT_SOURCE=/path/to/AstrBot` 可执行该源码中的实际 runner 和消息保存方法；测试不导入应用初始化代码。

将旧插件源码放在 `/tmp` 下的分析目录，额外设置 `MONITOR_COMPAT_SOURCE=/path/to/monitor-0.4.1` 和 `COMFY_COMPAT_SOURCE=/path/to/comfy-2.4.2` 可运行旧版本兼容测试。测试执行原有探针、重试检查、Comfy 批量工具及回收方法，并使用 AstrBot 真实本地工具执行方法；网关和渠道发送使用测试替身，不访问生产服务。

验证覆盖原生配置组件、渠道隔离、多级模型回退、默认永久文字缓存、每次读取来源、失效图片不复用、16 MB 大图拒绝、本轮临时文件删除，以及历史发言实现未变。

v0.2.2 验证包含监控先加载／后加载、反复重载、Comfy 正常及后台发送、合并转发、重复接管、重叠批次、任务取消、临时文件归属和 runner 释放。设置、历史发言、文字缓存和大图限制保持原样。
